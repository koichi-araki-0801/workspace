本書は pie-chart（円グラフ SVG レンダラ）を非開発者の端末へ配布・運用するための手順をまとめる。内部構造・ビルドの仕組みは別冊「pie-chart 詳細設計書」（14 章 exe 配布）を、検証コマンドの正典は `pie-chart/README.md`「検証」節を参照。

# 1. 配布方針

配布物は **`dist-exe/` の 4 点**（`pie-chart.exe` + `pie-chart-codesign.cer` + `OFL-BIZUDPGothic.txt` + `SIGNING-INFO.txt`）。実行に要るもの（CLI 本体・`subset-font`・harfbuzz wasm・フォント WOFF2・OFL 本文）はすべて exe の中に入っており、**`pie-chart.exe` 単体で動く**。exe の隣や上位ディレクトリの `fonts/` `node_modules/` は一切読まない（読むと署名の外にある書き換え可能なファイルからコードを実行する経路になるため。設計書 14 章）。配布先に Node.js のインストールは不要で、Windows 10 / 11 で起動できる。

# 2. exe をビルド

入口は 2 つあり、環境に応じて選ぶ:

| 入口 | 使いどころ |
|---|---|
| `pie-chart\scripts\build-exe.bat` | クリーンな単独環境向け。`npm install` からやり直してビルドする |
| `npm run build:exe`（`pie-chart/` 直下） | 開発機向け。既存 `node_modules` のままビルドのみ行う |

ビルドは前提が崩れたら落ちる（Node < 20.12、`scripts/sidecar-pins.json` と実解決した `subset-font` 版・wasm ハッシュの不一致、バンドル内の wasm 参照が 1 箇所でない）。署名鍵の thumbprint（`scripts/signing.local.json` または環境変数 `PIECHART_SIGN_THUMBPRINT`）が無い場合もビルド失敗になる。鍵は `scripts/new-signing-cert.bat` で 1 回だけ作る（`NonExportable`・有効期間 1 年。社内 PKI があればそちらから発行する）。

ビルド後は **`pie-chart\scripts\verify-dist.bat` を必ず通す**。次の 3 点を機械検査し、1 つでも欠ければ非ゼロ終了する（設計書 14 章）:

1. `dist-exe/` の中身が上記 4 点だけであること（`fonts/` `node_modules/` などの sidecar が復活していないこと）。
2. exe の署名者 thumbprint が期待値と一致すること。
3. exe を空ディレクトリへ 1 個だけコピーして描画した SVG が、開発版（tsx）の出力と **byte 一致**すること。

# 3. 配布・起動

1. `dist-exe/` の 4 点を共有フォルダや配布メディアで対象端末へ渡す。`pie-chart.exe` だけを別の場所へコピーしても動くが、ライセンス文書 `OFL-BIZUDPGothic.txt` は exe と一緒に保管させる。
2. 初回起動時に SmartScreen の警告が出たら「詳細情報」→「実行」で通す。**同梱の `pie-chart-codesign.cer` を配布先の信頼ストア（信頼されたルート証明機関 / 信頼された発行元）へ登録する運用は行わない**（1 台の PC が持つ鍵が全端末の信頼アンカーになる構造を作らないため）。`.cer` と `SIGNING-INFO.txt` は「どの鍵で署名した配布物か」を確認するための同梱物である。
3. コマンドプロンプトから実行する（GUI は無い）:

```
pie-chart.exe list
pie-chart.exe one --sample asset_gbca_pdf_like --output-file out\sample.svg
pie-chart.exe one --xlsx data.xlsx --sheet Sheet1 --range A2:B11 --output-file out\chart.svg
pie-chart.exe license
```

`--xlsx` には `--sheet` と `--range` の両方が必須で、`--range` は見出し行を含めないデータ行のみの 2 列（左=名前、右=数値）を指定する。

# 4. DB 入力（--sql）を使う場合

**exe 版は DB(SQL Server) 入力に対応しない**。ネイティブドライバ `msnodesqlv8` は exe にバンドルできず、exe の隣へ後から置く運用は署名の外にあるコードを実行時に読む経路そのものになるため採らない（`loadDbItems` は exe 実行を検知して明示エラーで止まる）。DB 入力が要る場合は開発環境（Node + `npm run cli -- one --sql ...`）で生成する。

開発環境での接続は Windows 統合認証で、資格情報は保存しない。クエリの `assertLooksLikeSelect` は先頭キーワードと文中の `;` を見る形式チェックであって権限境界ではなく、読み取り専用は接続アカウントの権限（対象 DB で `db_datareader` だけを持つログイン）で担保する。

# 5. 運用・トラブル対応

| 事象 | 対処 |
|---|---|
| SmartScreen の警告が出る | 「詳細情報」→「実行」で通す（3 章の手順 2）。証明書の信頼登録は行わない。頻発して業務に支障がある場合は社内 PKI 発行の署名鍵への切り替えを検討する |
| `SEA asset ...` / `external module resolution is disabled ...` で始まるエラー | exe に埋め込んだ資産・モジュールの参照が許可リスト外に出ている。配布物の破損か版ずれを疑い、`verify-dist.bat` を通した exe を再配布する |
| 出力 SVG が異常に大きい（数 MB） | exe 版はサブセット失敗時にフルフォントへ退避せずエラーで止まるため、通常は起きない。起きた場合は開発版の出力の可能性があるので、生成元を確認する |
| `--sql` がエラーになる | exe 版は非対応（4 章）。開発版なら msnodesqlv8 の未導入、接続アカウントの権限、クエリの形式のいずれかをエラーメッセージで切り分ける |
| 出力が開発版と異なる | 正常時は byte-identical（2 章）。異なる場合は exe とソースの版ずれを疑い、再ビルドして `verify-dist.bat` を通す |
| 署名の有効期限が切れた | 鍵は有効期間 1 年でタイムスタンプ無しの構成では既配布 exe の署名も無効になる。期限の 1 か月前に再発行・再署名・再配布する |

# 6. 更新の出し方と `out/_baseline` の規律

- **exe の更新**: ソース更新 → 検証（`npm run batch` → `npm run batch:diff` で `out/_baseline` と byte 一致、`npm run verify` 通過）→ ビルド（2 章）→ `verify-dist.bat` 通過 → `dist-exe/` の 4 点を差し替え配布、の順を守る。
- **意図した出力変更**（配置改良等）を配布する場合は、先に `out/_baseline` を更新して差分ゼロを確認してからビルドする。baseline 更新と exe 配布が食い違うと、次回の回帰検証で意図変更と退行の区別がつかなくなる。
- ライセンスファイル `OFL-BIZUDPGothic.txt` は配布物から外さない（フォント再配布の条件。設計書 13 章）。exe 単体でも `pie-chart.exe license` で同じ本文を表示できる。
