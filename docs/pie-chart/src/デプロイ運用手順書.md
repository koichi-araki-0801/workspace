本書は pie-chart（円グラフ SVG レンダラ）を非開発者の端末へ配布・運用するための手順をまとめる。内部構造・ビルドの仕組みは別冊「pie-chart 詳細設計書」（14 章 exe 配布）を、検証コマンドの正典は `pie-chart/README.md`「検証」節を参照。

# 1. 配布方針

配布物は **`dist-exe/` の未署名 2 点**（`pie-chart.exe` + `OFL-BIZUDPGothic.txt`。`--sign` で署名したときは `pie-chart-codesign.cer` と `SIGNING-INFO.txt` を加えた 4 点）。既定は未署名で、配布先に AppLocker / WDAC の発行者ルールが無ければ署名は要らない。実行に要るもの（CLI 本体・`subset-font`・harfbuzz wasm・フォント WOFF2・OFL 本文・DB ドライバ）はすべて exe の中に入っており、**`pie-chart.exe` 単体で動く**。exe の隣や上位ディレクトリの `fonts/` `node_modules/` は一切読まない（読むと署名の外にある書き換え可能なファイルからコードを実行する経路になるため。設計書 14 章）。DB ドライバだけは、DB を使うときに exe が一時フォルダへ書き出して読み込む（4 章）。配布先に Node.js のインストールは不要で、Windows 10 / 11 で起動できる。

# 2. exe をビルド

入口は 2 つあり、環境に応じて選ぶ:

| 入口 | 使いどころ |
|---|---|
| `pie-chart\scripts\build-exe.bat` | クリーンな単独環境向け。`package-lock.json` どおりに `npm ci` で依存を入れ直してビルドする |
| `npm run build:exe`（`pie-chart/` 直下） | 開発機向け。既存 `node_modules` のままビルドのみ行う |

ビルドは前提が崩れたら落ちる（Node < 20.12、`scripts/sidecar-pins.json` と実解決した `subset-font` 版・wasm ハッシュの不一致、バンドル内の wasm 参照が 1 箇所でない、`msnodesqlv8` の版・ドライバのハッシュの不一致、ドライバを `dlopen` できない）。DB 機能つきの exe は開発機（pnpm / Node 24）でだけ作る。ドライバがビルドに使った Node のメジャー版でしか読めないためで、`build-exe.bat`（Node20 の単独環境）は DB 機能を外して作る（`--no-db`）。署名は `--sign` を付けたときだけ行い（`node scripts/build-exe.mjs --sign`）、そのとき署名鍵の thumbprint（`scripts/signing.local.json` または環境変数 `PIECHART_SIGN_THUMBPRINT`）が無ければ、あるいは署名に失敗すればビルド失敗になる。鍵は `scripts/new-signing-cert.bat` で 1 回だけ作る（`NonExportable`・有効期間 1 年。社内 PKI があればそちらから発行する）。

ビルド後は **`pie-chart\scripts\verify-dist.bat` を必ず通す**。次の 4 点を機械検査し、1 つでも欠ければ非ゼロ終了する（設計書 14 章）:

1. `dist-exe/` の中身が想定どおり（未署名は 2 点、署名ありは 4 点）であること（`fonts/` `node_modules/` などの sidecar が復活していないこと）。
2. 署名ありなら署名と thumbprint が期待値と一致すること、未署名なら NotSigned であること。
3. exe を空ディレクトリへ 1 個だけコピーして描画した SVG が、開発版（tsx）の出力と **byte 一致**すること。
4. `pie-chart.exe db-check` が成功し、実行ごとのフォルダ（`%TEMP%\pie-chart-db\...`）が残らないこと。DB 機能を外した exe を配らないための検査である。

# 3. 配布・起動

1. `dist-exe/` の中身（未署名は 2 点、`--sign` のときは 4 点）を共有フォルダや配布メディアで対象端末へ渡す。`pie-chart.exe` だけを別の場所へコピーしても動くが、ライセンス文書 `OFL-BIZUDPGothic.txt` は exe と一緒に保管させる。
2. 初回起動時に SmartScreen の警告が出たら「詳細情報」→「実行」で通す。**署名付き（`--sign`）の配布物に同梱される `pie-chart-codesign.cer` を配布先の信頼ストア（信頼されたルート証明機関 / 信頼された発行元）へ登録する運用は行わない**（1 台の PC が持つ鍵が全端末の信頼アンカーになる構造を作らないため）。`.cer` と `SIGNING-INFO.txt` は「どの鍵で署名した配布物か」を確認するための同梱物である。
3. コマンドプロンプトから実行する（GUI は無い）:

```
pie-chart.exe list
pie-chart.exe one --sample asset_gbca_pdf_like --output-file out\sample.svg
pie-chart.exe one --xlsx data.xlsx --sheet Sheet1 --range A2:B11 --output-file out\chart.svg
pie-chart.exe one --fund 0331A --base-date 2026-09-30 --chart-type 資産配分 --db-name usrap --output-file out\chart.svg
pie-chart.exe db-check --db-name usrap
pie-chart.exe license
```

`--xlsx` には `--sheet` と `--range` の両方が必須で、`--range` は見出し行を含めないデータ行のみの 2 列（左=名前、右=数値）を指定する。

# 4. DB 入力（ストアド）を使う場合

exe 版も DB 入力に対応する。ストアドを `--fund` / `--base-date` / `--chart-type` の 3 つで呼び、
Windows 統合認証で接続する（資格情報は保存しない）。

- 前提: 実行するユーザーの Windows アカウントが対象ストアドを実行できること（権限の付け方は
  DB 管理者が決める）。配布先に ODBC Driver 17 for SQL Server（または 18）が入っていること。
- ストアド名の既定は `dbo.pie_chart_items`（仮置き）。実際の名前は環境変数 `PIE_DB_PROC` で指定する。
- exe はドライバを `%TEMP%\pie-chart-db\` 配下へ書き出して読み込む。AppLocker / WDAC / EDR が
  `%TEMP%` からの DLL 読み込みを止める端末では動かない。導入前に配布先で
  `pie-chart.exe db-check --db-name <DB>` を実行し、全段階が OK になることを確かめる。
  ポリシーの有無は次でも確かめられる:

  ```powershell
  Get-AppLockerPolicy -Effective -Xml
  (Get-CimInstance -Namespace root\Microsoft\Windows\DeviceGuard -ClassName Win32_DeviceGuard).UsermodeCodeIntegrityPolicyEnforcementStatus
  Test-Path HKLM:\SOFTWARE\Policies\Microsoft\Windows\Safer\CodeIdentifiers
  ```

- 発行者ルールで許可する運用にする場合は、`--sign` で署名した exe を配る。

# 5. 運用・トラブル対応

| 事象 | 対処 |
|---|---|
| SmartScreen の警告が出る | 「詳細情報」→「実行」で通す（3 章の手順 2）。証明書の信頼登録は行わない。頻発して業務に支障がある場合は社内 PKI 発行の署名鍵への切り替えを検討する |
| `SEA asset ...` / `external module resolution is disabled ...` で始まるエラー | exe に埋め込んだ資産・モジュールの参照が許可リスト外に出ている。配布物の破損か版ずれを疑い、`verify-dist.bat` を通した exe を再配布する |
| 出力 SVG が異常に大きい（数 MB） | exe 版はサブセット失敗時にフルフォントへ退避せずエラーで止まるため、通常は起きない。起きた場合は開発版の出力の可能性があるので、生成元を確認する |
| `[db:<段階>]` で止まる | `db-check` の結果で段階を確かめる。load はアプリ制御・ウイルス対策、connect は接続先と権限、query はストアドの定義（結果セットが 1 つ・2 列か）を疑う |
| ストアドのエラーメッセージが文字化けする | ドライバ（msnodesqlv8）の既知の制限。メッセージは英数字で書くか、エラー番号で判別する |
| 出力が開発版と異なる | 正常時は byte-identical（2 章）。異なる場合は exe とソースの版ずれを疑い、再ビルドして `verify-dist.bat` を通す |
| 署名の有効期限が切れた | 鍵は有効期間 1 年でタイムスタンプ無しの構成では既配布 exe の署名も無効になる。期限の 1 か月前に再発行・再署名・再配布する |

# 6. 更新の出し方と `out/_baseline` の規律

- **exe の更新**: ソース更新 → 検証（`npm run batch` → `npm run batch:diff` で `out/_baseline` と byte 一致、`npm run verify` 通過）→ ビルド（2 章）→ `verify-dist.bat` 通過 → `dist-exe/` の配布物（未署名は 2 点、`--sign` のときは 4 点）を差し替え配布、の順を守る。
- **意図した出力変更**（配置改良等）を配布する場合は、先に `out/_baseline` を更新して差分ゼロを確認してからビルドする。baseline 更新と exe 配布が食い違うと、次回の回帰検証で意図変更と退行の区別がつかなくなる。
- ライセンスファイル `OFL-BIZUDPGothic.txt` は配布物から外さない（フォント再配布の条件。設計書 13 章）。exe 単体でも `pie-chart.exe license` で同じ本文を表示できる。
