本書は pie-chart（円グラフ SVG レンダラ）を非開発者の端末へ配布・運用するための手順をまとめる。内部構造・ビルドの仕組みは別冊「pie-chart 詳細設計書」（15 章 exe 配布）を、検証コマンドの正典は `pie-chart/README.md`「検証」節を参照。

# 1. 配布方針

配布物は **`dist-exe/` フォルダ一式**（`pie-chart.exe` + `pie-chart-codesign.cer` + `fonts/` + `node_modules/`）。単一 exe だけでは動かず、フォント WOFF2 と `subset-font` の依存ツリーを exe 隣から外部参照する（バンドルするとフォントサブセットが効かず SVG が肥大化するため。設計書 15 章）。配布先に Node.js のインストールは不要で、Windows 10 / 11 で起動できる。

# 2. exe をビルド

入口は 2 つあり、環境に応じて選ぶ:

| 入口 | 使いどころ |
|---|---|
| `pie-chart\scripts\build-exe.bat` | クリーンな単独環境向け。`npm install` からやり直してビルドする |
| `npm run build:exe`（`pie-chart/` 直下） | 開発機向け。既存 `node_modules` のままビルドのみ行う |

ビルド後、`dist-exe/pie-chart.exe` に対する動作確認として `one --sample` の 1 枚生成と、開発版（tsx）出力との **byte-identical 確認**を行う（設計書 15 章。exe と tsx で出力が一致するのが正常）。

# 3. 配布・起動

1. `dist-exe/` フォルダごと共有フォルダや配布メディアで対象端末へ渡す（フォルダ構成を崩さない）。
2. 初回のみ `pie-chart-codesign.cer` を「信頼されたルート証明機関」へ登録する（`certutil -addstore Root pie-chart-codesign.cer`）。SmartScreen の警告を抑止するためで、登録しなくても実行自体は可能。
3. コマンドプロンプトから実行する（GUI は無い）:

```
pie-chart.exe list
pie-chart.exe one --sample currency_10 --output-file out\sample.svg
pie-chart.exe one --xlsx data.xlsx --output-file out\chart.svg
```

# 4. DB 入力（--sql）を使う場合

DB(SQL Server) 入力はネイティブドライバ `msnodesqlv8` を要するため exe には同梱していない。利用する端末でのみ `dist-exe/node_modules/` へ `msnodesqlv8` を追加配置する（設計書 15 章）。接続は Windows 統合認証で、資格情報は保存しない。SELECT 単文のみ許可され、複文・更新系クエリは拒否される。

# 5. 運用・トラブル対応

| 事象 | 対処 |
|---|---|
| SmartScreen の警告が出る | 初回の証明書登録（3 章の手順 2）を実施。登録済みでも出る場合は .cer の再配布版か確認 |
| 出力 SVG が異常に大きい（数 MB） | フォントサブセット失敗の兆候。`dist-exe/fonts/` と `dist-exe/node_modules/` が exe の隣に揃っているか（フォルダ構成を崩していないか）を確認 |
| `--sql` がエラーになる | `msnodesqlv8` の未配置（4 章）か、SELECT 以外のクエリ。エラーメッセージで切り分ける |
| 出力が開発版と異なる | 正常時は byte-identical（2 章）。異なる場合は exe とソースの版ずれを疑い、再ビルドする |
| フォントが標準ゴシックで出る | `fonts/` の WOFF2 欠落。配布フォルダを作り直す |

# 6. 更新の出し方と `out/_baseline` の規律

- **exe の更新**: ソース更新 → 検証（`npm run batch` → `npm run batch:diff` で `out/_baseline` と byte 一致、`npm run verify` 通過）→ ビルド（2 章）→ byte-identical 確認 → `dist-exe/` を差し替え配布、の順を守る。
- **意図した出力変更**（配置改良等）を配布する場合は、先に `out/_baseline` を更新して差分ゼロを確認してからビルドする。baseline 更新と exe 配布が食い違うと、次回の回帰検証で意図変更と退行の区別がつかなくなる。
- ライセンスファイル `fonts/OFL-BIZUDPGothic.txt` は配布フォルダから外さない（フォント再配布の条件。設計書 14 章）。
