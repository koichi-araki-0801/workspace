pie-chart は CLI とライブラリで使う円グラフ SVG レンダラである。本書は CLI からの生成・一括処理・Excel 入力・DB(SQL Server)入力・ビューア確認・exe 配布の手引き。内部構造は別冊「pie-chart 詳細設計書」を参照。

# 1. セットアップ

実行系は環境で使い分ける（従来の `run.bat` / `run.ps1` は Node メジャー版を自動判定していたが、2026-06 にラッパを廃止して手動運用へ移行）。

- **開発機（pnpm / Node 24 系）**: リポジトリ直下で `pnpm install`、各コマンドは `pnpm --filter pie-chart run <script>`（または `pie-chart/` 内で `pnpm run <script>`）。
- **pnpm の無い旧 Node 20 系の単独環境**: この `pie-chart/` フォルダ内で `npm` を直接叩く。

```
npm install
npm run check   # tsc --noEmit で型チェック
npm run batch   # 87 サンプル一括生成
npm run verify  # 自動検証
```

> [!INFO] 旧 Node 20 系向けに `package.json` の `overrides` で **vite を `^6` に固定**している（vite@8 / rolldown は Node 20.16 で EBADENGINE になるため）。pnpm はルートの `overrides` しか見ないので、開発機は最新 vite@8 のまま＝npm 経路だけ vite@6 へ切り替わる。vite/vitest はテスト専用で、`cli` / `batch` / `verify` / `build:exe` は tsx・esbuild 経由のため SVG 出力には影響しない。

# 2. CLI の使い方

CLI は `npm run cli -- <command>`（または直接 `tsx src/cli.ts <command>`）で実行する。コマンドは `list` / `one` / `batch` の 3 種。

| コマンド | 用途 |
|---|---|
| `list` | 利用可能なサンプル名を一覧表示 |
| `one` | 1 枚の SVG を生成（入力 1 系統 + `--output-file` 必須） |
| `batch` | 複数 SVG を一括生成（既定で全サンプル） |

例:

```
npm run cli -- list
npm run cli -- one --sample asset_gbca_pdf_like --output-file out/test.svg
npm run cli -- one --data-file data/example.json --output-file out/test.svg
npm run cli -- one --data-json '[{"name":"A","value":60},{"name":"B","value":40}]' --output-file out/test.svg
npm run cli -- one --xlsx data.xlsx --sheet Sheet1 --range A2:B11 --output-file out/test.svg
npm run cli -- one --sql "SELECT 区分, 比率 FROM dbo.資産配分" --db-name usrap --output-file out/test.svg
npm run cli -- batch --output-dir out/svg
npm run cli -- batch --input-dir data --output-dir out/svg
```

# 3. 入力の指定方法

`one` の入力は次のいずれか 1 系統（`--output-file` は必須）。

- `--sample <name>` … 同梱サンプル（`list` で確認）。
- `--data-file <path.json>` … `{name, value}` 配列の JSON ファイル。
- `--data-json '<json>'` … `{name, value}` 配列を直接渡す。
- `--xlsx <file> --sheet <name> --range <A1:B11>` … Excel の範囲。
- `--sql <SELECT文>` … SQL Server へ SELECT を投げて結果から取り込む（下記 5 章）。

`batch` は既定で全サンプル。`--samples a,b,c` で対象を絞れる。`--input-dir <dir>` 指定時はそのディレクトリ内の `*.json` を一括処理する。

# 4. Excel 入力の決まり

> [!WARN] `--range` は **2 列固定**（左=name、右=value）。3 列以上 / 1 列はエラー。

- **ヘッダ行は指定しない**（データ行のみ渡す）。先頭行が「区分」「比率」のような文字列だと `Non-numeric value at row N` で落ちる。
- 空行はスキップ、name 空欄や value の数値変換不可は明示エラー。
- 数式セルは結果値、リッチテキスト / ハイパーリンクも展開して取り込む。
- `exceljs` 依存は `src/xlsx_loader.ts` に隔離（`parseRange` / `loadXlsxItems`）。

# 5. DB（SQL Server）入力の決まり

`--sql <SELECT文>` で SQL Server の結果セットから直接取り込む。接続は **Windows 統合認証**固定で、資格情報は持たない。

- **単一の SELECT 文のみ**。複文（文中 `;`）・非 SELECT（UPDATE/DELETE 等）は拒否する。
- 列解決は Excel と同思想。`--name-col` / `--value-col` を**両方**指定すれば列名で、無指定なら結果セットの**先頭 2 列**を name/value とする（3 列以上で未指定はあいまいエラー）。
- 接続先は `--db-server`（既定 env `DB_SERVER` / `localhost`）・`--db-name`（既定 env `DB_NAME`）。ODBC ドライバは既定 `ODBC Driver 17 for SQL Server`（env `DB_ODBC_DRIVER` で変更可）。

> [!INFO] ネイティブドライバ `msnodesqlv8` は `optionalDependencies`。**遅延 require** のため未導入でも他入力（sample/json/xlsx）と `tsc` は動く。DB 入力を使うときだけ導入する。接続・SQL 依存は `src/db_loader.ts` に隔離（`buildConnectionString` / `assertSelectOnly` / `rowsToItems` / `loadDbItems`）。

例:

```
npm run cli -- one --sql "SELECT 区分, 比率 FROM dbo.資産配分" --db-name usrap --output-file out/test.svg
npm run cli -- one --sql "SELECT name AS n, val AS v FROM t" --name-col n --value-col v --output-file out/test.svg
```

# 6. 全件生成とビューア確認

- `npm run batch` … 全 87 サンプルを `out/svg_js/` に出力し、`out/compare.html`（A4 想定・1 ページ 12 件のページ送り）を更新する。ブラウザで `out/compare.html` を開いて目視確認できる。
- `npm run verify` … 生成済み SVG のラベル数・bbox オーバーラップ・円内侵入・引出線交差・viewBox はみ出し・引出線屈曲数を自動検証する（対象ディレクトリは引数指定可。既定は `out/svg_js`）。

> [!INFO] `verify` は生成済み SVG を読むため、先に `batch` を実行しておくこと。出力は決定的なので、同じ入力なら毎回同一の SVG が得られる。

# 7. exe 配布（非開発者向け）

Node も tsx も無い端末へ配るには実行ファイルを生成する。入口は 2 つで、依存の入れ方が異なる。**配布物は `dist-exe/` フォルダ一式**。

- **`scripts/build-exe.bat`（ダブルクリック / 旧 Node20 系の単独環境向け）**: ビルド前に `node_modules` / `package-lock.json` を消して **`npm install` をクリーン実行**してから exe を作る。事前の手動 install は不要で「このフォルダだけ」で完結する。
- **`npm run build:exe` / `pnpm run build:exe`（= `node scripts/build-exe.mjs`、開発機向け）**: install はせず、既存の `node_modules` でビルドのみ行う（pnpm ワークスペースの依存解決を保つ）。

```
dist-exe/
├── pie-chart.exe          — Node SEA 実行体（cli を esbuild で単一 CJS 化して inject）
├── pie-chart-codesign.cer — 自己署名の公開証明書（配布先で信頼登録すると署名が Valid に）
├── fonts/                 — 埋込元の woff2（BIZ UDPGothic 400/700）
└── node_modules/          — subset-font + 依存（harfbuzzjs wasm 等）
```

- 使い方は CLI と同じ: `pie-chart.exe one --sample asset_gbca_pdf_like --output-file t.svg` など。出力は tsx 版と **byte-identical**。
- フォントと `subset-font` は exe に埋め込まず**外部参照**する（`fonts/` と `node_modules` を exe と同じ場所に置く）。これによりサブセット埋込が効き出力 SVG が軽い。
- ビルド時（Windows）に `scripts/sign-exe.ps1` が exe を**自己署名**で SHA256 署名する。SmartScreen を抑止するには配布先で同梱 `pie-chart-codesign.cer` を信頼登録する（管理者権限）:

```
certutil -addstore Root pie-chart-codesign.cer
certutil -addstore TrustedPublisher pie-chart-codesign.cer
```

> [!INFO] DB 入力（`--sql`）はネイティブ `msnodesqlv8` を要するため exe には含めない。利用時は `dist-exe/node_modules` へ `msnodesqlv8` を追加する（描画・Excel 入力は追加不要で動く）。
