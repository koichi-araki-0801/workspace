# トラブルシュート（症状 → 原因 → 対処）

新人が最初にハマりやすい事象の一覧。ここに無い事象は各プロジェクトの `README.md` と
`docs/<project>/src/設計正典.md` の「触る前のチェックリスト」を参照する。

## `.ps1` を保存しただけで CI（check:comments）が赤くなる

- **原因**: 日本語を含む `.ps1` は **UTF-8 BOM 必須**という規約がある（cp932 環境での
  文字化け回避）。多くのエディタは既定で BOM 無し保存するため、保存し直しただけで規約違反になる。
  同様に `.ps1` には同名 `.bat` ランチャの併設が必須。
- **対処**: VS Code なら右下のエンコーディング表示 → 「エンコード付きで保存」→
  「UTF-8 with BOM」。規約の詳細は `docs/コメント規約.md` の言語別付録 C / D。

## コミット直後に長い処理や gh の警告が出る

- **原因**: post-commit フックがオフラインバンドルの GitHub Releases 公開
  （`offline/publish-offline-bundle.ps1`）を実行している。これは**公開担当者が
  `git config offline.publish true` で opt-in した clone だけ**で動く（GitHub は
  公開担当者のオンライン環境限定の運用。新規 clone では skip の 1 行が出るだけ）。
- **対処**: opt-in していないのに走る場合は `git config --get offline.publish` を確認して
  `--unset` する。opt-in 済み環境で一時的に止めたいときは `OFFLINE_PUBLISH_SKIP=1`。
  ベストエフォート設計のため失敗してもコミット自体は成立している。

## ローカル CI は通ったのに GitHub Actions で coverage が落ちる

- **原因**: pre-push の affected CI（`pnpm run ci:affected`）と領域別 CI は速度優先で
  **coverage 85% ゲートを通さない**（vitest の coverage はラン全体で 1 つしか持てないため）。
  ゲートはフル `pnpm run ci` と GitHub Actions だけが掛ける。
- **対処**: PR 前にフル `pnpm run ci` を一度流す。なお GitHub Actions はオーナーの
  オンライン環境向けの保険であり、オフライン運用環境での正はローカル `pnpm run ci`。

## pie-chart で `npm run batch:diff` が使えない / baseline が無いと言われる

- **原因**: 比較基準 `out/_baseline` はローカル生成物（git 管理外）で、clone 直後には存在しない。
- **対処**: コミット済みのクリーンな状態で `npm run batch` → `npm run baseline:accept` を
  1 回実行して基準を作る。詳細は `pie-chart/README.md` の「検証」節。

## コミットしたら意図しない内容がステージされていた（editor 配下）

- **原因**: pre-commit の lint-staged が `editor/**` に `biome check --write` をかける。
  自動修正しきれない Biome エラーが残っているとステージが入れ替わる事故がある。
- **対処**: editor 配下を変更したコミットの前に
  `pnpm exec biome check --write editor/<対象>` を先行実行して状態を確定させる。

## editor で型エラーが大量に出る（web/server の型解決が壊れる）

- **原因**: web / server の型チェックは **`@editor/shared` の先行ビルドが前提**。
  shared が未ビルドだと参照先の型が見つからず連鎖的に赤くなる。
- **対処**: `pnpm typecheck`（先行ビルド込み）を使う。個別に tsc を叩かない。

## push が遅い / push で CI が走って落ちる

- **原因**: pre-push フックが affected CI（変更領域のみ）を実行する。共有ファイル
  （`package.json` / lockfile / 各種 config）を触るとフル CI にフォールバックするため長くなる。
- **対処**: 落ちた内容はローカルで `pnpm run ci:<領域>`（またはフル `pnpm run ci`）を流せば
  同じ内容を再現できる。タグのみの push は CI をスキップする仕様（正常動作）。
