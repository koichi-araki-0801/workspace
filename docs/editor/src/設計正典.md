- ポートは **server=24680 / Vite dev=24681** で固定。起動は `editor/start.bat`（引数順不同:
  `dev`/`prod` × `rest`（既定）/`local` × `lan`）。`rest` は SQL Server + 認証必須、`rest lan` は
  `HOST=0.0.0.0` + HTTPS（PFX 方式・`HTTPS=true` opt-in。無証明書時は HTTP +
  `COOKIE_SECURE=false` フォールバック）。
- テンプレ実体はリポジトリ**外**の `dataRoot`（既定 `../../editor-data`。ネスト git 回避、
  初期化は `editor/scripts/init-data-repo.bat`）。**本体=ファイル/git、DB=認証・監査・カタログと
  ファンド属性の参照**が基本方針。テンプレートの一覧・作成済みの判定はファイルで行い、DB の台帳は
  持たない。作成タブの会社・ファンド・シリーズは、同じサーバの `Rep1` を usrap の sproc から
  3 部名で読む（直接 SQL はしない）。ファイル名の会社コードは `Rep1` の委託会社略称。

## 中核原則

- **編集 2 系統**（根幹。詳細は設計書 6.1 節）: 編集タブ = `tpl.filled`（per-fund 実値）+
  ハイライト**無し** / 作成タブ = `toFilled(tpl.html, 共通sample)` + ハイライト**有り**。
  経路判定は `route.query.created === '1'` のみ。rest の `tpl.filled` は dataRoot
  `filled/<id>.html`（別ツールが置く値入り HTML。値は差込済みで、往復用の印は持たない）。承認は
  申請の `origin` で `filled/`（edit）と `templates/`（create）を書き分け、値入り HTML はプレビュー・比較・結合 PDF でも nunjucks を通さない。
  `status:'draft'`（pending だけの id）は作成経路（`?created=1`）で開く。`created` query を
  出す規則は `features/templates/editorRoute.ts` の `editorRoute`、pending の判定は同ファイルの
  `opensAsCreate` で、一覧・承認タブ・プレビューの戻る導線が共用する。編集経路（`origin='edit'`）
  の申請・承認は `filled/<id>.html` の存在を要求する（server `assertFilledPresentForEdit`、
  local `assertEditSubmissionAllowed`）。後者は内部で `resolveFilled` を引くほか、
  本文が空の申請も拒否する（空文字を「filled 無し」の印に使うための local 限定の規則で、
  server 側に対応は無い）。local の値入り HTML の有無は `resolveFilled`（`filledOverride` →
  作成承認済みなら無し → fixture）で決める。作成承認後に旧 `filled/` が残る rest とは意図的に
  違う（local は別ツールの配置運用を持たない）。
- **ID の 2 つの形**: 値入り HTML（`filled/`）は基準日ごとに別物なので `会社_ファンド_基準日_版種`、
  テンプレート（`templates/`）は基準日で使い回さないので `会社_ファンド_版種` で、区切りの数で見分ける
  （`shared/src/domain/template.ts`。`parseTemplateFileName` / `parseSkeletonFileName` /
  `parseAnyTemplateFileName`）。`templates/` は 3 つ区切りだけ、`filled/` は 4 つ区切りだけ、
  `pending/`・下書き・メモ・申請・作成履歴はどちらの形も受け、形はパスを組み立てる関数が強制する。
  `templates/` に残った 4 つ区切りは作成済み・コピー元・一覧に数えない。版の一覧（`filled/` の git
  履歴）は 3 つ区切りに空を返す。作成済みのテンプレートは作成タブから作成経路（`?created=1`）で開き、
  申請 → 承認で上書きする。生成は作成済み・承認待ちの作成申請・同意の無い作業中（下書きか
  `pending/`）を 409 で止め、下書きと `pending/` は生成器が成功した後に捨てる（コメントとパーツ変更
  履歴は残す）。作り直した id の同じタブの編集状態（Undo と下書きの持ち主）も捨てる。
- `toFilled` の値の差込は、固めていない要素ではテキストの位置だけ。属性値の中の Jinja は原文のまま
  残し、チップにも値にもしない。固めた要素（下記）は表示用に属性値の中まで値を入れて描くが、保存では
  常に原文へ戻す。ゆえにデータ連動チャート（Jinja 属性で座標を出す SVG/CSS）は、固められない限り
  作成タブで値の入った形に見えないので、テンプレに入れない。
- **作成タブの往復は、判断を原文の位置で 1 回だけ行う**: `toFilled` は原文を `lexJinja`
  （`shared/src/jinja/jinjaLex.ts`。関所と共用する唯一の字句解析）でトークンに切り、`htmlScan.ts` で
  HTML の構造を読み、`fillAnalysis.ts` で印を置ける位置と固める要素を決めてから値入り HTML を書く。
  - ブロックの範囲は HTML コメントの印（`<!--jinja-rt:o:…-->` と `<!--jinja-rt:c:…-->`）で表し、
    採用した枝の前後の原文を印に持たせる。採用した枝への編集はその枝へ書き戻し、他の枝は原文のまま
    保つ。for の 2 回目以降の繰り返しは `<!--jinja-rt:x:…-->` の後ろに並ぶ表示専用の写しで、保存時に
    捨てる。表・`select` の文脈に置かれた範囲を持たない文と Jinja コメント（`{% set %}`・`{# … #}`）は
    `<!--jinja-rt:t:<base64>-->` で表す（チップを置けない位置でもコメントは動かない）。
  - 印を置けない位置（表の行の間の値・SVG の中・本文中の `<style>` 等）は、それを含む最小の安全な
    要素を固める（値入りで見せ、保存は原文）。表の中で固めた範囲は `div.jinja-frozen-body`
    （`display: contents`）で包み、表の外へ追い出されたテキストもこの div の中に留める。固めた SVG の
    子孫は SVG の名前空間で描く部品型（`jinja-frozen-svg-in`）にする。
  - `toFilled` は自分の出力を `toTemplate` で戻して原文と比べ（自己検査）、食い違えば本文全体を
    固める。比べるときは `normalizeForRoundTrip` で、GrapesJS が捨てる空白を同じ規則で捨て、テキスト
    位置の Jinja をコメントへ置き換えて位置を固定し、属性の順序を揃える。
    - 既知の限界: Worker で走る自己検査は linkedom で読む（Worker にはブラウザの DOM が無い）。表の中身の
      追い出し（foster parenting）などブラウザだけで起きる崩れは自己検査では見つからず、保存時の `toTemplate`
      の検査（ブラウザの DOM で読む）が例外にして受け止める。
  - キャンバスの読み込みは、本文の断片を `parse:html:before` で `<body>` に包んでから解析させる。
    包まないと、先頭の要素より前のコメント（ブロックの開きの印）がブラウザの構文規則で body の外へ出て
    消える。
  - `toTemplate` は断片を文書（`asDocument`）に包んでから解析し、戻した結果のブロックの対応と編集用の
    印の残りを検査し、崩れていれば例外にする。server と web local も、作成・編集の両経路の申請本文と
    確定書込（server `confirmedWrite` / local `putContentOverrides`）で同じ印を 400 で拒否する（定義は
    `shared/src/security/editingMarkers.ts` の `findEditingMarkers` 1 つ。原文をブラウザと同じ規則で
    読む走査に、`lexJinja` と最短一致の 2 通りの区切りで Jinja を空白・`J` で伏せた写しの走査を足し、
    伏せた写しはコメントの中まで読む走査も掛け、どれかで見つかれば印とする）。
    - 既知の限界: 関所が調べるのは原文で、描画結果ではない（描画結果はサンプル・ファンドの値しだいで形が変わるので、関所の判定を値に依存させない）。Jinja でタグ名や属性をつなぎ合わせた形
      （`<{{ "span" }} data-jinja>`）は `J` で伏せた写しの走査で見つかるが、印をまるごと Jinja の式で
      組み立てた形（`{{ "<span data-jinja>" }}`）は見つからない。
    - 範囲の印の開きと閉じを両方消すと（文字編集で印をまたいで消した場合など）、そのブロックは採用した枝の
      中身だけを残した地の本文として保存され、例外にはならない。作成経路の申請の確認（`PreviewView.vue` の
      `submitForReview`）は、元のテンプレートと申請する本文の、閉じを持つ Jinja のブロックの開きの数
      （`jinjaLex.ts` の `countJinjaBlockOpens`。`if` `for` `raw` `verbatim` と中身を木にしないブロック）を比べ、
      減っていれば確認の説明に「元のテンプレートより Jinja のブロック（{% if %} など）が N 個少なくなっています。
      意図した削除でなければ、申請せずに編集画面で確かめてください。」を足す（申請は続けられる。どちらかが字句
      として読めなければ足さない）。編集経路は値入り本文で `toTemplate` を通らないので比べない。承認画面の差分
      でも Jinja の消失として見える。
  - 編集タブの値入り HTML は印を持たない。本番の `filled/` も local の fixture（`genFilled.ts` が
    `renderPlainFilled` で作る）も同じ。`toFilled` は作成タブ専用。
  - 旧形式の印（要素の属性で持つ `data-jinja-open` 等）は読まない。旧形式の下書きは編集画面を開いた
    ときに破棄してトーストで知らせ、確定版から開き直す（`legacyDraft.ts` の `isLegacyDraft`）。
    作成経路の下書きは旧形式の属性が 1 個でもあれば、編集タブの下書きは編集用の印が 1 個でもあれば
    旧形式とみなす（編集タブの本文は印を持たないため）。
  - ループの行の枠（琥珀色の点線、`#f59e0b`）と、固めた要素の枠（灰色の点線、レイヤー名
    「編集不可（Jinja）」）は、どちらも `.jinja-vars-highlight` の配下にだけ書き、作成タブにだけ出す。
- 画面は Repository **契約**にのみ依存。local/rest の実装差し替えで画面コードは無改修。
- 確定保存は**申請 → 承認**の 2 段階ゲート。実ファイル + git 反映は `applyConfirmedWrite` が
  唯一の関所（自己承認拒否・却下理由必須・監査ログ）。
  同じ申請者・同じテンプレ（大文字小文字を区別しない）・同じ経路（`origin`）・同じ本文（HTML と CSS の
  完全一致）の承認待ちが既にあれば、新しい申請を作らず 409（`code: 'REVIEW_DUPLICATE'`）で返す
  （二重クリック・再送。`filledHtml`・`cssBaseline`・`changedSummary` は本文の付随物なので照合しない）。
  server と web local で同じ規則・同じ code・同じ文言にする。server は重複の検査から件数上限の検査を
  経て `writeReview` までを申請専用の鎖（`reviewRepo.ts` の `withSubmitLock`）で直列化する。重複を
  上限より先に見るのは、上限ちょうどでの二重クリックを「上限」ではなく「重複」として返すため。承認の鎖（`withReviewLock`）と
  分けるのは、承認が git コミットを含んで遅く、申請をその後ろで待たせないため。照合は候補のメタを
  絞ってから本文を読んで hash で比べ（`reviewFiles.ts` の `findDuplicatePendingReview`。hash はメタに
  保存しない）、本文を読めない申請は判定から外す（壊れた 1 件のせいで同じ人がそのテンプレへ申請
  できなくなるのを避ける。その申請自体は承認時に止まる。ファイルが無い以外の失敗は警告ログに残す）。印の検査など入口の検査の後ろに置くので、
  入口で拒まれる申請は重複かどうかを見る前に止まる。web はこの 409 を受けたら、成功と同じく編集
  セッションを片付ける（同じ内容が既に承認待ちに載っているため）。
- エラーは throw でなく `Result`/`AppError`（7 種 kind・message は日本語でユーザー表示可能）。
- **交付版⇄全体版 パーツ自動同期**: 承認の完結後に `pairSyncService` がベストエフォートで
  ペア版種のテンプレへパーツ単位の変更を転写する（失敗しても承認は成立）。ポリシーの正典は
  **パーツカタログ台帳の `同期既定` 列のみ**（`同期`/`非同期`/`交付版のみ`/`全体版のみ`/NULL=
  未判断。ペア個別オーバーライドは持たない）。実行状態（`lastSynced`・競合）は
  `dataRoot/sync/<pairKey>.json`（git 管理**内**。`pairKey` はテンプレートが `会社_ファンド`、値入り HTML が
  `会社_ファンド_基準日`）。自動で書くのは「同期既定=`同期` かつ
  前回同期以降 source だけが変わった」パーツの転写のみで、削除・初期差分・両側変更（競合）・
  挿入位置不明はスキップして人間に返す。ペア側で削除したパーツ（同期したことがある = `lastSynced`
  を持つもの）は source にあっても戻さず、source が前回同期から変わっていなければ競合「ペア側削除」、
  変わっていれば「ペア側削除・ソース変更」として記録する（`lastSynced` は据え置く）。同期したことの
  無いパーツがペア側に無いのは「まだ写していない」だけなので、今までどおり挿入する。状態ファイルは
  ペアで 1 つで、バナーは両方の版の編集画面に出るため、「ペア側」という言い方は見る画面で指す側が
  変わる。そこで競合にパーツを消した側の版種（`deletedIn`）を持たせ、バナーは
  `p-123#1〔全体版で削除〕`・`p-123#1〔全体版で削除・交付版で変更〕` のように版種で書く
  （`web/src/lib/pairSyncText.ts`。`deletedIn` の無い記録は `〔種類〕` へ倒す）。両方の版から消えれば
  状態から消え、ペア側に同じ内容で戻せば同期済みになり、別の内容で戻せば「両側変更」へ移る。
  転写は生テキストの span 置換（DOM round-trip 禁止 =
  非対象パーツは byte 不変）。対象は `data-part-id` 付きパーツのみ（カタログ外パーツは
  常に対象外。同期させたいパーツは `data-part-id` 付与 + カタログ登録で昇格する）。
  CSS はテンプレ単位（`<会社>_<ファンド>_<版種>.css`）なので、ペアの CSS 2 枚（`…_交付版.css` ⇔
  `…_全体版.css`）も転写の対象になる。変更の検出は GrapesJS の書き出し形どうしで行う: web は確定版を
  canvas に読み込んだ直後の `getCss` を `cssBaseline` として申請に載せ（`sessionStorage` にも置く）、
  `shared/src/css/cssRules.ts` の `mergeCssRuleChangesFromBaseline` が `cssBaseline` → 申請の CSS で
  変わった規則（追加・変更・削除）だけを取り出す。ペア側の同じ規則が承認前のファイル（原文）と同じなら
  当て、違えば（版種固有に直してある）競合として飛ばす（外部ツールの原文と GrapesJS の書き直し形を直に
  比べると、編集していない規則まで変わって見えるため、検出と照合で物差しを分ける）。規則のキーは
  セレクタ規則が囲む at-rule の並び + 正規化セレクタ、`@page` 系が前置き、`@font-face` が
  `font-family` + `font-weight` + `font-style` で、比較は書式の違いを除いて行う（`sameCssRule`）。
  同じキーの重複規則は 1 つの規則として識別し、宣言が空の出現を外して前から出現ごとに比べて当てる
  （GrapesJS は重複を別々の規則のまま持つ）。ペア側の出現の形が原文と違えば（宣言の配り方を変えた・
  1 本にまとめた等）、対応が取れないので競合にする。
  競合はテンプレのペアキー（`cssSyncPairKey`。`会社_ファンド`）の同期状態ファイルの `css` 欄に記録し、
  本文の競合と同じバナーに出す（`getPairSyncStatus` の `cssConflicts`）。競合が消えるのは、両版の規則が
  一致したとき（両版ともエディタの書き出し形になったとき）。CSS の転写は承認 1 回につき 1 回で、本文の
  ペア同期が動く承認のときだけ動く。`cssBaseline` の無い申請（公開 API・`cssBaseline` を持たない申請）と、
  承認前の CSS を読めないときは CSS の転写だけを飛ばしてログに残す（承認は成立し、本文の同期は続ける）。
  下書きがあるのに `cssBaseline` が無いまま申請画面を開くと、「このまま申請するとペアの版種へ CSS が
  写りません。編集画面から開き直してください」の注意帯を出す。保存・申請・`cssBaseline` の CSS は
  `getCss({ keepUnusedStyles: true })` で書き出す（CSS は基準日をまたいで共有するので、ある文書で未使用の
  規則も消さない。承認後の CSS ファイルは全規則が GrapesJS の書き出し形になる）。`confirmedWrite` の
  `pair-sync` が CSS を書けるのはこのためで、型で CSS の書き込みを塞がないのは、交付版と全体版が別ファイルに
  なり、承認した側だけが直ると版種間で見た目がずれるため。規則への分割は既存の字句走査（`walkCss`）の
  上に組み、依存を足さない。
  - **規則のキーの正規化**（`cssRules.ts` の `canonicalSelector` ほか）: GrapesJS はセレクタと media の
    文字列をブラウザの CSSOM（`selectorText` / `mediaText`）から取り、ブラウザは `.a>.b` を `.a > .b`、
    `:before` を `::before` のように書き直す。原文の書き方しだいでキーが割れないよう、キーを作るときに
    次をそろえる。セレクタでは、コメントを空文字にし、空白の連続を 1 つにし、結合子（`>` `+` `~`）と `,`
    の前後・`(` の直後・`)` の直前の空白を消し、旧式の擬似要素 4 つ（`:before` `:after` `:first-line`
    `:first-letter`）を `::` にし、型セレクタ・擬似クラスと擬似要素の名前・属性名を小文字にし、
    `:nth-child` 系 4 つの引数（An+B）を Chromium の書き出し形（`even` → `2n`、`odd` → `2n+1`、`+5` → `5`、
    `0n+1` → `1`、`1n` → `n`）にする。at-rule の前置きでは、名前を小文字にし、コメントを空白にし、
    `@media` は文字列の外を全部小文字にし、`@media` `@supports` `@container` の `:` の後ろと括弧の内側の
    空白を消し（`@media(…)` は `@media (…)`）、`@page` はページセレクタを空白 1 つで続けた形
    （`@page :first`）にする。クラス名・id・属性値・文字列の中身・エスケープした文字・`@container` と
    `@layer` の名前の大文字小文字は区別したまま残す（別の規則を同じキーに畳まない）。規則の本文
    （`text`）は原文のまま。
  - **セレクタの並び（`.a, .b{…}`）は照合のときだけ 1 セレクタずつに展開する**: GrapesJS はクラスだけ
    （または id だけ）の並びを 1 セレクタ 1 規則に分けて持つので、照合の経路（`foldedCssRuleTexts`・
    `mergeCssRuleChanges`・`mergeCssRuleChangesFromBaseline`）では原文側も含む 4 つの CSS すべてを展開した
    「見かけの規則」で突き合わせる（公開の `splitCssRules` は展開しない）。ペア側への書き戻しは物理の規則
    ごとにセレクタごとの結果を集めて 1 つにまとめる。全部消えれば規則ごと消し、全部が同じ新しい本文なら
    並びのまま本文だけ置き換え、片方だけ変わった・消えたときは元の規則の位置で 1 セレクタずつに分割する
    （カスケードの順は変わらない。セレクタは原文の書き方を残す）。`:is(.a, .b)` のような括弧の中の `,` は
    展開せず、並びの中に正規化後に同じキーになるセレクタが 2 つ以上ある規則も展開しない（下の照合不可に
    なる）。
  - **照合不可**: 正規化と展開をしても、`cssBaseline` にあるのに承認前の原文に無いキーは残りうる。その
    規則の変更は、ペア側の同じ規則を引けないので当てられず、削除は「ペア側に無い = もう消えている」と
    取り違えて黙って残す。そこで、このキーは変更でも削除でも競合 `kind: '照合不可'`（転写元の版種
    `sourceEdition` 付き）として記録する（`CssMergeResult.unmatched`）。同じ向きの承認では、ペア側に
    そのキーが無い間は残す。解消するのは、ペア側も編集画面を通して承認され、両版のキーがそろったとき
    （以後は普通の競合と同じ判定）。バナーは `書式 .a〔照合不可〕` と出し、末尾に「照合不可の書式は、
    ペアの CSS が編集画面を通っていない書き方のため写せませんでした。ペアも編集画面で開いて申請・承認
    すると、次から照合できます。」を足す。承認直後の通知は件数だけで、種類は見せない。
  - **古い競合のキーの読み替え**: 同期状態ファイルの `css.conflicts[].ruleKey` は前の正規化のキーで
    残っていることがある。`computeCssSync` は、記録のキーが両版のどちらかに今のキーとしてあればそのまま
    使い、無いときだけ `canonicalCssRuleKeys` で読み替える（読み替えが冪等でない形、たとえば大文字の
    at-keyword の文を変えてしまうと、どちらの版にも無いキーになって「両版に無い = 解消」で黙って消える
    ため）。並びのキーは 1 セレクタずつに分かれ、各件が元の `detectedAt` を引き継ぐ。
    - 移行期の注記: 前の正規化はコメントを空白にしていたので、セレクタの中にコメントを書いた規則の古い
      競合は読み替えで戻せず、次の承認で消えることがある。読み替えは承認のときに行うので、承認が
      1 回通るまでは状態 API（バナー）に古い形のキー（`.a,.b` を 1 件）が出ることがある。承認が 1 回通れば
      読み替えが済み、以後は出ない。

- **本文の `<style>` は原文のまま運び、canvas では複製で効かせる**（`features/editor/bodyStyle.ts`）:
  GrapesJS のパーサは本文の `<style>` を取り除いて規則を CSS の入れ物へ移し、`load` の `setStyle` が入れ物を

  名前空間で子要素を持たない本文の `<style>` は、パーサが取り除く前に中身の無い置き場の要素へ差し替え、原文

  Undo の snapshot・下書きの再読込はどれも原文を通り、読み込むたびに同じ部品へ戻る。往復用の印を保存へ
  出さないので、印を拒む編集タブの関所とも、`toTemplate` で原文へ戻す作成タブとも両立する。原文は DOM の
  属性ではなくモジュール内の対応表で渡す（利用者の HTML が置き場を名乗って任意の HTML を保存へ書かせない）。

    数え方（`pageItems`）は置き場と `<style>` を数えない。

  `<div class="pagebreak"></div>`（区切り）を置き、テンプレの CSS に `.pagebreak{break-after:page}` を書いて改ページを

  動く）・ページ線・Inspector の改ページ・警告が同じ関数を使う。呼び出し側ごとに数え方が違うと、ページ数・

    見ない（保存に失敗しても遷移は止めない）。失敗していれば、遷移のときに `onBeforeRouteLeave` の

    （セッション切れの転送・ログアウト）は保存を試みるが、結果によらず確認せずに離れる（ログインし直す
    まで保存できないので、留まらせても保存できない）。route を経ないアンマウント（タブを閉じる・
    再読込）は `beforeunload` に任せる。
- **パーツの修正履歴の 1 件は web が作る id で識別する**: セッション内の履歴（`editorSession` の
  `partHistory`）と、画面を開くたびに読み直す永続履歴の両方に同じ 1 件が載るので、web が 1 件ごとに
  UUID を作り（`lib/newId.ts`。`crypto.randomUUID` が無い HTTP の LAN 公開では `getRandomValues` で作る）、
  セッション内の 1 件と記録要求（`RecordPartChangeRequest.id`。省略可能）に同じ id を使う。表示
  （`usePartEditHistory` の `displayHistory`）はセッション内 → 永続の順に並べ、同じ id の 2 件目以降を
  落とす。server は `id` が無い古い呼び出しには今までどおり `pt-<UUID>` を付ける。id の無い既存の行
  （手で直した行など）には、読むときに内容から決まる `legacy-<sha1>` を付けて返す（ファイルは書き換え
  ない。同じ行は毎回同じ id になる）。記録の時点では id の重複を除かない（表示で除く）。
- **起動時のズームは 100%**: 編集キャンバスは画面に合わせず A4 実寸で開き、window・ペインの
  resize でも倍率を据え置く（追随させるのは overlay と縦配置だけ）。画面へのフィットは
  Ctrl+0 / % ボタンの手動操作のみ（`useZoomFit.fitToView`）。狭い画面では横スクロールになる（仕様）。
- **編集画面の赤入れ表示は既定 OFF**: 開いた直後は差分を出さず、上部バーのボタンで明示したときだけ
  表示する。
- **保存内容に GrapesJS 由来の揮発物を載せない**: 幾何（幅・余白）は inline `style` 属性に
  保存する（`avoidInlineStyle:false`。CssRule `#id` は使わない — 自動 id が保存内容の一部になる）。
  `getBodyHtml()` は明示属性に無い `id` を落とす（選択で StyleManager が id セレクタを作ると
  `getHtml()` が自動 id を出力し、draft / Undo snapshot に混入して再読込で構造キーが合わなくなる）。
  canvas に GrapesJS の `protectedCss` を当てない（`protectedCss:''`。PDF と同じ CSS で描く。
  保存 CSS へ混入して load のたび積み増すのを止める）。この変更のスパイク検証で確認したのは
  table の auto layout が `box-sizing` の差を吸収した 1 テンプレのみで、flex/grid +
  `width:%` + padding/border で寸法を出すテンプレは canvas 上の見えが変わりうる（実画面での
  確認が必要。box-sizing が要るならテンプレの CSS 側で宣言する）。`avoidInlineStyle` は GrapesJS
  0.23 系で deprecated 扱いで、false にしても `getCss()`（`CssGenerator.buildFromModel`）は
  inline style を持つ component へ無条件で `#<自動id>{…}` をミラーする（対応する `id` 属性は
  HTML 側に出ないため必ず死んだセレクタになる） — `buildFromModel` はこの設定値を生成のたびに
  読むだけなので、`getCss()` は `editor.getConfig().avoidInlineStyle` を呼び出しの間だけ
  `true` に立てて `ed.getCss()` を呼び、`finally` で元へ戻す（ミラーを生成元で止める。
  component 木の走査や文字列除去をこちら側で再実装しない — GrapesJS の内部形式・述語と
  二重実装すると版が上がるたびズレうる）。同期呼び出しの間だけの切替なので他経路
  （`patchSelectedStyle` 等）には影響しない。既定 `forceClass:true` は component 生成時に
  inline style が非空だと自動生成クラスへ丸ごと
  移し替えるため、`forceClass:false` も併せて必要（無いと load の再パースで幾何が
  inline style → 自動クラスへ化けて round-trip が壊れる）。Undo ミラーは `:v2`（旧ミラーは
  読まない）。機械検証は `web/test/saveFormat.dom.test.ts`。
  - GrapesJS 0.23.6 のパーサは、`@media` / `@supports` の中に入れ子にした `@font-face` を
    `@media screen{font-family:…;src:…}` の形に崩す。編集画面はその `@font-face` を GrapesJS に通さず運ぶ:
    開くとき（`load`）に `splitNestedFontFaces`（`lib/cssCarry.ts`。字句は `collectCssStructure`）で取り出し、
    外側の前置きで包み直した原文の文字列のまま持ち、残りだけを `setStyle` へ渡す。canvas では本文の `<style>`
    と同じく CSS の複製（`syncCanvasCssCopy`）へ丸ごと入れて効かせ、保存の `getCss` の末尾へ改行区切りで戻す
    （下書き・CSS の baseline・汚れの判定・スナップショットはすべて `getCss` を通る）。外側のブロックの普通の
    規則は GrapesJS に残す（ブロックごと動かすとカスケード上の位置が変わり、PDF の見た目が変わるため）。
    - 既知の短所: 運んだ `@font-face` は CSS の中で末尾へ動く（GrapesJS も最上位の `@font-face` を末尾へ動かす。
      `saveFormat.dom.test.ts` の「最上位の @font-face は GrapesJS 自身が末尾へ動かす」）。
      ペア同期は規則をキーで突き合わせるので、位置の移動は変更にならない（`cssRules.test.ts`）。
- **テキスト編集中の Undo は、追記と操作を別々の 1 手にする**: GrapesJS はテキスト編集中の入力を
  DOM にだけ持ち、モデルへは編集を閉じるとき（`disableEditing` の `syncContent`）に反映する。Undo の
  snapshot はモデルから取るので、編集を開いたまま操作すると追記がその操作の 1 手に混ざる。マウスなら
  押した時点で GrapesJS が編集を閉じるが、キーボードでボタンを押したときやハンドルを押したときは閉じない。
  - Undo 可能な操作の入口（改ページ・配置の初期化・パーツの追加・移動・削除・Inspector の数値・
    Undo/Redo のボタン）は、テキスト編集を閉じてモデルへの反映を終えてから走らせる
    （`textEditFinish.ts` の `afterTextEdit`）。上限時間内に閉じられなければ、操作を取りやめて
    トーストで知らせる。開いたまま走らせると、`beginUndo` の操作では追記が独立した 1 手にならず、
    `pushUndo` の操作では Undo の順序が逆になる。
  - `disableEditing` は 1 回の編集につき 1 回しか呼ばない。閉じている途中や上限で打ち切った後に
    呼ばれても、同じ Promise を待ち直す。呼び直すと `rte:disable` が 2 回出て、修正履歴にテキストの
    編集が 2 件残る。
  - 余白・幅のハンドルのドラッグは、押下で pointer を捕まえて（`setPointerCapture`）受ける。
    ハンドルは canvas の iframe の上に重なるので、捕まえないと外へ出た移動と離す操作が iframe へ
    流れる。drag の間だけ iframe の `pointer-events` を切り替える方法は採らない（iframe の状態を
    書き換えて戻す経路が増える）。
- **編集・プレビュー画面はタブの下に展開し、アプリヘッダとタブは 1 行 56px**（2026-09）:
  `/edit/:id` と `/preview/:id` は `MainLayout` の children（URL は不変）。`MainLayout` は
  `h-screen` の内側スクロールで、`route.meta.flush` のルートは本文の余白を持たず残りの高さを
  全部使う。タブ点灯は `features/layout/tabOf.ts` の純関数で、編集・プレビューは
  `route.query.created === '1'` なら「テンプレート作成」、でなければ「編集」に写す（2 系統の
  根拠を表示へ写すだけで、値の差込やハイライトには関与しない）。タブを押すと
  `stores/tabMemory.ts` が覚えた「そのタブで直前に見ていた画面」へ戻る。ただし承認タブは直前画面へ
  戻さず常に `/reviews` を開き、対象は編集タブで開いているテンプレートから決める（次項）。点灯している
  タブを押したときも直前画面（＝今の画面）へは戻さず、そのタブの一覧を開く。編集画面の上部バーの
  「一覧へ戻る」はブラウザ履歴を辿らず、経路のタブ（`tabOf`）の一覧へ送る。他タブやプレビューを
  経由すると履歴の直前は一覧でなくなり、編集タブは編集中の画面へ戻すので、履歴を辿ると一覧へ
  行く道が無くなるため。ヘッダ帯のロゴ（ツール名）は編集の一覧へのリンク。タブごとの直前画面の
  記録は `MainLayout` の `watch(route.fullPath)` で行う（`router.afterEach` ではない。
  `MainLayout` は children 全体で常駐し、タブを持たない画面は `tabOf` が弾く）。ヘッダ帯のロゴは
  副文言まで残し、ゾーン間は `gap-8` と `ml-auto` で空ける。機械検証は
  `e2e/tabbed_layout.spec.ts`・`e2e/header_layout.spec.ts`（アプリヘッダと上部バーの両方を
  明示セレクタで測る。素の `header` はアプリヘッダを掴む）。
  - 対応する画面幅の下限は 1400px（本文の最大幅を 1400px 未満へ狭めない、却下済み設計「本文の最大幅を 1400px 未満へ狭める」と対）。1400px・1440px
    で上部バーが 1 行に収まることを `e2e/header_layout.spec.ts` が測る。下限より狭い幅では上部バーが 2 行に
    折り返すことがある（`flex-wrap`。崩さずに全部出すための仕様）。
- **承認タブは「編集タブで開いているテンプレート 1 件」の申請を縦に並べて 1 件ずつ決着する**
  （2026-09）: 精査キューの一覧は持たない。対象は `?template=<id>`（承認待ちバッジ・上部バーが
  渡す）→ 編集タブの直前画面（`tabMemory`）の `/edit/:id` の順で決め（`resolveReviewTarget.ts`）、
  どちらも無ければ編集タブでテンプレートを開くよう促す。申請の状態は
  `pending / approved / rejected` の 3 つ（保留は撤去。3 状態の外（旧 `held` など）の申請は
  1 件ずつ読み飛ばし、一覧全体は落とさない）。要約箱 3 つで絞り、新しい順のアコーディオンに `ReviewDetail.vue`（申請 1 件の
  本体。組版 iframe 2 面）を載せる。**同時に展開できるのは 2 件**（`reviewAccordion.ts`。
  申請数に比例して iframe を持たせると承認者のブラウザが固まる）。各区画の右にコメントパネル
  （`CommentPanel.vue`）を置き、宛先パーツは区画内のセレクトで選び、行クリックは見た目比較の
  該当ページへ `gotoPage` で送る（アンカーはページ単位）。決着しても画面に留まり、区画が
  決着済み表示へ変わる。コメントは承認可否と独立（関所には触れない）。
  `pageAnchors` は index ごとに after → before で引き、修正前にしか無いページは修正前パネル
  だけが動く。コメント宛先の選択は区画（申請）ごとで、投稿先は呼び出し側が明示する。宛先は
  確定版の構造から作るため、申請側にだけ在る追加パーツには宛てられない。行クリックは
  文字差分タブ表示中でも見た目比較へ切り替えて送り、確定版に無いパーツの行は不活性にする。
  編集 canvas 側の構造キー（`partKey.ts` の `canvasRawKey`）は GrapesJS がライブ要素へ付ける
  自動 `id` を使わず、モデルの明示属性から `id` を引く。確定版 HTML を静的に読む側
  （`reviewPartMaps.ts`・compare）とキー集合が一致することが不変則で、`partKey.test.ts` が
  機械固定する（自動 `id` 入りのキーで保存された過去のコメント・修正履歴は新キーと一致せず
  「削除済みパーツ」扱いになる。移行は行わない）。キーの書式は文書全体での `<アンカー>#<通し番号>` で
  ページを含まない。旧形式（`ページ/パーツ`）のキーも移行せず、編集画面で件数だけを警告する（改ページの項）。
- **編集セッションはブラウザタブの寿命**（2026-09）: タブ遷移・プレビュー往復・リロードでは
  未確定の編集を破棄しない（離脱ガードは未保存の変更を保存し終えるまで待つだけ。上の autosave の項）。閉じる前の警告は dirty で
  出す。閉じた後の再オープンでは下書きを破棄して確定版から開く — 閉じる瞬間の通信は
  不確実なので、`sessionStorage` のトークン（`lib/draftOwner.ts`）と `localStorage` の所属
  記録を `loadForEdit` が比べて判定する。明示的な「編集を破棄」導線は置かない。同一テンプレの
  複数タブ・複数利用者の同時編集は非サポート（後から開いた側が先の下書きを破棄しうる）。
  所属キーが端末にまだ無いとき（旧ビルドからの移行直後）は、最初に開いた下書きを現在の
  セッションのものとして引き継ぐ（1 回限りの猶予。デプロイ後の最初のリロードで作業中の
  下書きを一斉に失わないため）。
  画面の UI 状態も同じセッションの一部でプレビュー往復で戻す（`stores/editorSession.ts` の `ui`）。
  倍率・ページ表示・右ペインのタブ・赤入れ表示（既定 OFF）・guide は localStorage へ永続しリロードでも戻る。
  **`allowEdit` と選択は永続しない**（リロード後は安全側の既定 OFF・未選択）。

- **守りを足すときは「その関門を通らない経路」を列挙する**（中核原則。ここを数え落とす形で
  4 件の迂回が生まれた）。列挙は文章ではなく**機械検証**として置く
  （`server/test/guardCoverage.guard.test.ts`）。現在覆っている列挙は 4 つ:
  - nunjucks がテンプレの字面から外部の値へ触る経路 = **プロパティ参照 / グローバル参照 /
    フィルタ解決**の 3 本。`memberLookup` と `contextOrFrameLookup` だけを包んでいた版は、
    `env.filters` が素のオブジェクトリテラルであることを突かれて `{{ 1|valueOf }}` から
    Context → Environment → `Function` へ到達できた（`"constructor"` は**文字列引数**なので
    名前遮断に掛からない）。`env.filters` は own-property だけの null プロトタイプ表にする。
  - 走査器が **raw text として読み飛ばす要素**と、その中身を検査する分岐の対。
    `<svg><style>` / `<svg><title>` は foreign content で raw text にならず、内側の
    `<img onerror>` が生きる。`title`/`textarea` で一度学んだ事実は、raw text 扱いする
    **全要素**へ一様に効く。
  - zip で**展開を許す拡張子**と、外部参照を検査する拡張子。`.md` は vivliostyle が原稿として
    組版するので、markdown 標準の画像 1 行が無検査で通っていた（HTML のタグ走査では拾えない）。
  - **requirements を pip へ渡す入口**。検査が publish 経路にしか無く、他の 3 入口が素通り
    だった。`--no-index` は requirements 内の `--find-links <URL>` を止めないので省略できない。
- **`Host` ヘッダは検査する**（DNS リバインディング）。攻撃者ページは自ドメインの DNS を
  後から `127.0.0.1` へ向け替えられ、ブラウザは同一オリジンのつもりで要求を出すため
  SameSite も CORS も効かない。唯一食い違うのが `Host`。効きどころは**認証を課さない配備**
  （既定の local モード）で、そこでは実質「loopback に到達できること」だけが認可条件になる。
  判定は**ホスト名だけ**（ポートは見ない）。既定は loopback 名のみ、LAN 公開時だけこの機械が
  実際に持つ名前とアドレスを足す（`ALLOWED_HOSTS` で追加可）。`config.requireAuth` で
  出し分けない（設定 1 つでガードが消える形を作らない）。
- **上限は「大きさ」と「計算量」の 2 軸で持つ**。入力長・件数・ノード数はどれも大きさの上限で、
  100 バイト未満の入力に刺さる指数バックトラックを止められない。しかもサニタイザ自身が
  固まると、規定の失敗の仕方（読込ごと拒否 + 件数通知）にすらならない
  = **守るためのコードが守る対象を殺す**。正規表現は「同じ位置へ 2 通りで到達しない」形に書く。
- **件数上限はサイズ上限を守れない**。メモは 1000 件 × 64KiB = 64MiB がファイル上限 4MiB の
  16 倍で、件数を守ったまま読めないファイルを作れた。上限は**実際に書いたバイト数**で強制する。
- **degrade を書き込みの入力にしない**。「読めないときは空を返す」は読み取りを守る仕組みだが、
  read-modify-write の入力にすると**破壊**になる（メモ全件が 1 件へ潰れた。git 管理外で復元
  不能）。読み取り経路と書き込み経路で別の関数を用意し、後者は読めなければ例外にする。
- **承認者が見る画面の完全性は 1 つの要件として扱う**。差分装飾は CSS カスケードレイヤの
  「**重要宣言では優先順位が逆転する**」性質で守る（差分装飾を最初に宣言したレイヤへ置き
  `!important` を付ける。レイヤ宣言は申請者 CSS より**前**に出す）。レイヤ名は文書ごとに
  CSPRNG で変える。実ブラウザで検証した唯一の突破口が「名前を当てて同じレイヤへ高詳細度で
  書く」形だった。`display` は上書きしない（表セルのレイアウトを壊す）。資源上限で差分に
  出せなかった領域は**警告として明示する**（粒度が粗いだけの `coarse` と違い、領域そのものが
  見えていない）。
- **隔離レンダーホストの realm は要求ごとに閉じる**。隔離の単位は iframe ではなく realm で、
  使い回すと 1 度の脱出が以後の全描画の応答を偽装できる（承認画面は申請者の本文 → 現行版の
  順に描画するので、差分の「変更前」側を申請者が決められる）。費用は実測で 1 要求あたり
  約 10 ms。

## してはならないこと・却下済み設計（再提案しない）

- **`allowEdit` を永続する**: しない。編集許可はリロード後に安全側の既定 OFF から始める必要が
  ある（誤って未確認のテンプレへ編集可能な状態で着地させない）。プレビュー往復（同一セッション）
  でだけ `sess.ui` 越しに値が残るのは、それがリロードを跨がない in-memory の状態だから。
- **並行実装の drift 検査を「定数の一致」だけで済ませる**: しない。**両側に同じ穴がある形は
  一致検査では検出できない**（`SECURITY_HEADERS` の値は揃っていたのに、両方とも
  `send_error()` が返す応答を覆っていなかった）。付与の**やり方**まで検査する
  （`end_headers()` を override しているか）。
- **属性文脈で `esc()`（`quote=False`）を使う**: しない。`alt="{esc(...)}"` は原稿 1 行で
  属性を閉じて `on*` を持ち込める。属性値は `esc_attr()` を通す。
- **アクセストークンをコマンドライン引数へ載せる**: しない。プロセスのコマンドラインは同一
  ユーザーの他プロセスから読める（本リポジトリ自身が `Win32_Process.CommandLine` を読む）。

- **フォントを複数の配信パス（`fonts/` と `css/fonts/`）で配る**: しない。同じ実体が 2 つの

- **編集画面で画像の `src` を書き換えて表示する**: しない。文字編集・ペースト・ドロップの取り込み口が
  複数あり、戻し忘れの経路が残ると配信ルートの URL が保存内容（下書き・申請・確定）へ混入する。
  CSS の `content: url()` なら属性を一切変えずに済む。
- **`data:image/svg+xml` を共有の許可リスト（`ALLOWED_DATA_PREFIXES`）へ足す**: しない。テンプレの
  著者が未検査の SVG を data URI で直接書けるようになる。
- **画像をプレビューホストのワイルドカード（`/api/preview-host/*`）でも配る**: しない。SVG 検査を
  通らない配信経路ができ、同じ実体を複数の配信パスで配ることになる。
- **旧構成（`<dataRoot>/assets`・CSS の `url(../fonts/…)`・旧 `editor/data`）を理由に起動を止める**:
  しない（2026-10）。片付けはフォント移設パッチ（`editor/patches/2026-10-fonts-to-css/`）に任せ、
  サーバは残りを起動ログで警告するだけにする（`files/legacyLayoutCheck.ts`）。止めると、パッチを
  流す前の確認や生成を使わない運用まで止まる。流し忘れるとフォントと JS の欠けた PDF が成功扱いで
  出るリスクは了承済みで、運用手順書の更新手順で「フォント移設パッチは必須」と目立たせて補う。
- **文書直下基準の参照（`css/…` `images/…`）や `css/<fund>.css` との互換分岐を持つ**: しない（2026-10）。
  実データは文書位置基準（`../`）とテンプレ単位 CSS で、旧形式のデータは移行もしない。互換の分岐を残すと
  解決の物差しが 2 本になり、経路ごとに片方だけ直す形の食い違い（プレビューには出るが PDF には出ない等）を
  生む。
- **CSS の規則分割・転写に postcss などの依存を足す**: しない。遮断端末へ配る依存が増える。分割は既存の
  字句走査（`walkCss`）の上に組んだ `shared/src/css/cssRules.ts` で足りる。
- **ブロックの印を要素の属性に付ける**: しない。表の中の印は HTML パーサが追い出し、テキストだけの枝は
  表せない。コメントは表・SVG の中でも動かず、GrapesJS もそのまま書き出す。
- **旧形式の下書きを新形式へ変換する**: しない。旧形式の if は採用した枝しか持たず、退避した原文も壊れて
  いる場合があるので、変換結果を信用できない。
