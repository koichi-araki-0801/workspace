本書は Editor（運報自動化テンプレート編集 Web アプリ）の構造・データ抽象化・ドメインモデル・フェーズ2（REST + SQL Server）を記述する。一次資料は `editor/README.md`・`editor/CONTRIBUTING.md`・`shared/src/` の型と Repository 契約・`server/` 各層。

# 1. 概要・目的

Editor は、Jinja2 で作成された HTML/CSS テンプレート（ファンド報告書系）を非エンジニアが GUI で安全に編集し、サンプルデータを差し込んでプレビュー・PDF 出力できる社内 Web アプリである。

- **編集**: GrapesJS（レイアウト/CSS 中心）。`{{ }}` / `{% %}` / `{# #}` を壊さず温存（mask/restore）。
- **プレビュー**: ブラウザ内 Nunjucks で生 Jinja2 + サンプルデータを描画 → vivliostyle でページ組み表示。
- **PDF**: サーバ側 `@vivliostyle/cli` で生成。
- **作成**: 既存 Python 生成器を Express から `child_process` で呼び出し。
- **認証**: 独自認証（ログイン + 初回パスワード初期化）。テーマはブルー系（Tailwind v4 + shadcn-vue）。

# 2. 全体アーキテクチャ（npm workspaces）

pnpm workspaces で 3 パッケージ + データに分離する。パッケージマネージャは `pnpm@11.5.3+`、Node `>=24`。

| ワークスペース | 責務 |
|---|---|
| `shared/`（`@editor/shared`） | 共有 TS 型/DTO + `Result`/`AppError` + ドメイン + Repository 契約（型の真実源） |
| `web/` | Vue3 + Vite + Vue Router + Pinia + Tailwind v4 + shadcn-vue + GrapesJS + Nunjucks + vivliostyle |
| `server/` | Express + TS（PDF 生成 / ファイル索引 / Python 生成器アダプタ / フェーズ2 REST・SQL） |
| `data/` | テンプレ（.html）とファンド毎 CSS（サーバが参照） |

> [!INFO] `allowBuilds`（pnpm 11 ルール）で esbuild / vue-demi / @vivliostyle/cli / @biomejs/biome のビルドスクリプトを明示許可する。承認は `pnpm-workspace.yaml` 側で行う（`package.json` 側は無効）。

# 3. データ抽象化と差し替え点（核心）

画面/サービス/ストアは**集約ごとの Repository インターフェース**（`shared/src/repositories/*`）にのみ依存する。`web/src/api/local`（フェーズ1: localStorage 実装）と `server` の REST 実装（フェーズ2）が**同じ契約を満たす**ため、`web/src/api/repositories.ts` の **1 オブジェクトを差し替えるだけ**でデータソースを切替でき、画面コードは無改修。全メソッドは `Result<T>`（成功/`AppError`）を返す。

| Repository | 主なメソッド |
|---|---|
| `AuthRepository` | `login` / `logout` / `me` / `initPassword` |
| `TemplateRepository` | `getDropdownOptions` / `listTemplates` / `getTemplate` / `generate` / `resolveFund` / `listSeriesFunds` / `saveDraft` / `getDraft` / `confirmSave` / `getSampleData` |
| `HistoryRepository` | `getEditHistory` / `getPdfHistory` / `getCreateHistory` / `recordPdfExport` / `listVersions` / `getSnapshot` |
| `PartRepository` | `getPartClassificationOptions` / `listParts` / `getPartHistory` / `recordPartChange` |
| `UserRepository` | `listUsers` / `createUser` / `updateUser` / `resetUserPassword` |

- **フェーズ1（現状）**: フロント先行、`web/src/api/local/*Repo.ts`（localStorage 実装）。
- **フェーズ2（実装済・未デプロイ）**: 同契約の REST 実装に差し替え、SQL Server 連携。

# 4. ドメインモデル

主要な型（`shared/src/index.ts`）。

- **テンプレート同一性**: `TemplateAttributes`（`companyCode` 委託会社 / `fundCode` ファンド / `baseDate` 基準日 yyyymmdd / `editionType` 版種）。ファイル名は `company_fund_date_edition.html`。
- `TemplateMeta`（`id` / `attributes` / `fileName` / `status` draft|published / `updatedAt` / `updatedBy`）。
- `Template`（`meta` / `html` 生 Jinja2 / `css` ファンド毎共有 / `filled` 値差込済みで Jinja ソース温存）。
- `TemplateDraft`: 常時オートセーブの下書き（確定ファイルとは別）。
- `SampleData`: Nunjucks プレビューのコンテキスト（fundCode キー）。
- **ユーザー/認証**: `User`（`role` admin|editor|viewer / `mustChangePassword` 等）/ `LoginRequest` / `LoginResult` / `PasswordInitRequest`。
- **履歴 3 種**: `EditHistoryEntry` / `PdfHistoryEntry` / `CreateHistoryEntry`、加えてパーツ単位の `PartHistoryEntry`。
- **版スナップショット**: `TemplateSnapshot`（確定保存時の HTML/CSS を凍結。PDF/ページ画像は都度再描画して小さく保つ）/ `TemplateVersionMeta`（比較画面の版ピッカー行）。
- **パーツカタログ**: `PartClassification`（4 段階: カテゴリ/大/中/小）/ `PartCatalogItem`（`content` は GrapesJS 用 HTML 断片）。
- **DTO**: `DropdownQuery` / `DropdownOptions`（カスケード）、`GenerateRequest`（`isRedemption` 償還ファンド等）/ `GenerateResult`、`ConfirmSaveRequest`（`filledHtml` で記入済みインスタンスも保存）、`BuildInlineRequest`（vivliostyle へ渡す）。

# 5. Jinja2 タグ保護 + Nunjucks プレビュー

GrapesJS は HTML を DOM として扱うため、素のままでは `{{ }}` / `{% %}` / `{# #}` が壊れる。これを防ぐのが核心。

- `web/src/lib/jinjaMask.ts`: 編集前に Jinja タグを安全なプレースホルダへ **mask**、確定時に **restore** する。属性内 Jinja は静的化の制限がある。
- `web/src/lib/nunjucksRender.ts`: ブラウザ内 Nunjucks で生 Jinja2 + サンプルデータを描画（近似。非互換構文あり）。プレビュー専用で確定ファイルには影響しない。

# 6. GrapesJS 連携

- `web/src/features/editor/useGrapes.ts`: GrapesJS 初期化、キャンバス選択・rect 管理、zoom 制御、undo/redo。
- `web/src/features/editor/jinjaComponents.ts`: Jinja タグを保持する GrapesJS コンポーネント定義。
- アイコン/スタイルはローカル同梱（CDN 非依存。`cssIcons` をローカル化）。
- オーケストレーション: `useTemplateEditor()`（テンプレロード〜ライフサイクル）/ `useAutosave()`（下書き自動保存）/ `useSnapshotHistory()`（undo/redo スタック）。

# 7. プレビュー / PDF（vivliostyle）

- `server/src/vivliostyle/build.ts`: `@vivliostyle/cli` で PDF を生成（`/api/build` が入口、`/pdf` 相当を集約）。
- `server/src/vivliostyle/previewManager.ts`: プレビューを Vite proxy + stdout 捕捉で管理。
- `server/src/generate/pyTemplate.ts`: 既存 Python 生成器を `child_process` で呼ぶアダプタ（`/api/generate`）。
- PDF 出力時は `HistoryRepository.recordPdfExport` で履歴に記録する。

# 8. フェーズ2: REST + SQL Server（重点）

同じ Repository 契約を REST 実装で満たし、永続化を SQL Server へ移す。

## 8.1 REST API エンドポイント（抜粋）

| メソッド/パス | 役割 |
|---|---|
| `GET /api/health` | ヘルスチェック `{ok:true}` |
| `GET /api/templates/options` | `DropdownOptions`（委託会社/ファンド/基準日/版種） |
| `GET /api/templates` | `TemplateMeta[]`（属性で検索） |
| `GET /api/templates/series` | シリーズファンド一覧 |
| `GET /api/templates/:id` | `Template` 本体 |
| `GET/PUT /api/templates/:id/draft` | 下書きの取得 / 保存 |
| `POST /api/templates/:id/confirm` | 確定保存（`ConfirmSaveRequest` → `TemplateMeta`） |
| `GET /api/templates/:id/sample` | `SampleData` |
| `POST /api/build` | PDF 生成（`BuildInlineRequest`、vivliostyle） |
| `GET /api/preview/:id` | プレビュー（Vite preview への reverse proxy） |
| `POST /api/generate` | Python テンプレ生成 |
| `GET /api/parts` / `GET /api/parts/options` | パーツ一覧 / 分類候補 |
| `GET /api/history` / `GET /api/history/:type` | 履歴（edit/pdf/create） |
| `POST /api/auth/login` / `logout` / `password-init` | 認証 |
| `GET/POST/PUT /api/users...` | ユーザー管理（追加/更新/有効無効/PW初期化） |
| `GET /api/openapi.json` / `GET /api/api-docs` | OpenAPI 3.0 / Swagger UI |

## 8.2 認証

- `server/src/auth/`: 独自認証 + 初回パスワード初期化（Windows 統合認証を前提）。新規ユーザーの初期パスワードはユーザー ID に統一。
- パスワードハッシュは `server/scripts/hash-password.ts` で生成し seed に投入。

## 8.3 DB アクセス層

- ターゲット: **SQL Server 2012**、DB `usrap`、既存スキーマ `ug01`、テーブル接頭辞 `Rep1_運報自動化_Editor_`。
- **7 ゲートウェイ sproc**（`server/src/db/sprocNames.ts`）。すべての DB アクセスは第1引数 `@操作` で分岐する 1 本の sproc を通す。物理名（日本語）を 1 箇所に集約し、他所はハードコードしない。

| キー | sproc 名 |
|---|---|
| template | `[ug01].[Rep1_運報自動化_Editor_usp_テンプレート]` |
| history | `[ug01].[Rep1_運報自動化_Editor_usp_履歴]` |
| user | `[ug01].[Rep1_運報自動化_Editor_usp_ユーザー]` |
| session | `[ug01].[Rep1_運報自動化_Editor_usp_セッション]` |
| part | `[ug01].[Rep1_運報自動化_Editor_usp_パーツ]` |
| sample | `[ug01].[Rep1_運報自動化_Editor_usp_サンプルデータ]` |
| audit | `[ug01].[Rep1_運報自動化_Editor_usp_監査ログ]` |

- `server/src/db/sproc.ts` が SQL エラーを `Result` の `kind` へマップ: `THROW 50404`→not_found(404) / `50409`・一意制約2627/2601→conflict(409) / `50000`→validation(400) / その他→unexpected(500)。
- SQL Server 2012 互換のため `CREATE OR ALTER` / `OPENJSON` / `FOR JSON` / `STRING_AGG` は不使用。DDL/sproc/seed は `server/db/{ddl,sproc,seed}` に置き、全ファイル UTF-8 BOM 保存（日本語識別子 + sqlcmd cp932 対策）。

# 9. 技術スタック

- **shared**: TypeScript（strict）、DTO、`Result`/`AppError`。
- **server**: Express 5、Pino（logging）、Helmet（security）、msnodesqlv8（SQL Server、optional）、@vivliostyle/cli。
- **web**: Vue 3.5、Vite 8、Vue Router、Pinia、Tailwind v4、shadcn-vue、GrapesJS 0.23、Nunjucks 3.2。フォントは @fontsource でローカル同梱（CDN 非依存）。
- **Lint/Format**: Biome（husky + lint-staged でコミット時自動修正）。

# 10. ビルド・テスト・型チェック

```
npm run build
  → pnpm --filter @editor/shared run build
  → pnpm --filter server run build  (tsc -p tsconfig.json)
  → pnpm --filter web run build     (vue-tsc -b && vite build)
```

> [!INFO] `typecheck` は `@editor/shared` を先にビルドしておく必要がある（exports → dist の型解決のため）。

- テスト: `npm test`（vitest）。カバレッジは include 列挙＝テスト済みのみを対象に 80% 閾値。
- 整形 + Lint 一括修正: `npm run check`。CI 集約は `npm run ci`（`check:ci → typecheck → test:coverage → build → test:e2e`）。
